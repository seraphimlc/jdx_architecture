# BilionPass 业务全景说明文档设计规格

> **历史草稿，停止按此审批流程执行。** 用户于 2026-09-29 停用 superpowers。当前范围与事实优先级见冷启动文档最新说明；该草稿中排除 B 端商户等建议未经采用，不能替代已授权内容清单。

> 日期：2026-09-29  
> 范围：业务全景单文件 HTML 收尾  
> 项目性质：规划类文档项目，不是软件系统建设

## 1. 目标

把 BilionPass 当前已确认的业务事实整理成一份可直接打开和分享的单文件 HTML。文档服务三类读者：老板看战略落点，团队看业务版图与方向，CTO 用它继续梳理规划。

本阶段只完成业务架构层的收尾：补齐全景图中每个实体的说明页、统一页面表达、保证导航和链接完整。系统架构与单块系统的细化规划留到后续阶段。

## 2. 内容边界

内容以事实基座为最高优先级，内容源只是实现载体。内容只能来自以下材料中已确认的部分：

- `docs/业务与系统全貌备忘.md`
- `docs/平台大框架.md`
- 已确认的 `docs/site/content.mjs` 与 `docs/site/landscape.mjs`

未确认的信息必须进入“待确认”，不能被写成事实或规划承诺。页面只表达当前议题，不主动扩展到商务推进、资金细节或合规方案之外的问题。旧内容源与事实基座冲突时，以事实基座为准。

## 3. 信息结构

全景图按五个带组织：三端、分发出口、产品与服务内容、合作供给方、自有平台系统。大图中的框只显示具体实体名称和状态；每个框都能进入自己的说明页。

生成器先建立一份 canonical node registry：每个节点只有一个规范名称、一个稳定 ID 和一个页面。别名（例如“机场（含免税店）”与“机场（羽田 / 成田 / 关西）”）必须在 registry 中归一化后再参与链接与去重；不能用显示名称直接拼接页面。当前版图不收录 VIP 和没有对应全景框的旧待补项（例如 B 端商户），中枢职能可以作为独立说明页存在。

每篇说明页按固定顺序组织：

1. 一句话结论
2. 当前事实
3. 依赖关系
4. 下一步
5. 判断（仅保留已有明确判断）
6. 待确认
7. 事实来源

说明页允许附一张链式子图，但子图只表现已有事实链路，不承担新的推断。

## 4. 内容清单

说明页覆盖全景图中的所有节点，并补充不在大图中的平台中枢职能页。具体包括：

- 业务：行前购、空手行、优惠券、退税、门票、酒店、留学缴费、租 / 包车；行程规划作为功能说明，不作为业务交易线。VIP 已按 CTO 意见移出版图，本阶段不纳入节点。
- 供给：机场（含免税店）、佐川物流、JTR、Jalan、Canlead、fintech、自建能力
- 中枢：商品与库存、订单与履约编排、资金与结算、分发与授权、商户能力输出、内容与获客、风控与合规、账号与权限、主数据
- 端与出口：BilionPass、商户平台 · 商户 SAAS、管理平台 · 管理端；外部渠道、自有端（自己卖）、社媒与 KOL 作为分发结构节点，节点页必须说明其具体组成与已确认实体，不能把抽象分类词当作业务实体。
- 系统：综合平台 Portal、商户 SAAS、管理端、综合平台 API、行前购系统、空手行系统、自有端

现有富内容页要复用，不能重复进入“待补”导航。优惠券的当前接入形态统一为东航 API 对接；行程规划统一表述为功能；AI / GEO 归入内容与获客。不能残留“【待补】”占位，未知只能出现在“待确认”区域。

## 5. 生成与完整性规则

`tools/build-docs.mjs` 负责把内容源生成 `docs/site/index.html`，并在生成前校验：

- 节点名称没有重复；
- canonical node registry 中没有重复 ID、重复规范名称或未归一化别名；
- 每个全景图节点都有唯一说明页；
- 每个说明页只对应一个节点，且每个节点只有一个 route / DOM 页面；
- 每个富内容块都能挂到节点或生成独立中枢页，且与待补清单互斥；
- `pendingBlocks` 为空；
- 成品中不存在“【待补】”占位；
- 导航不重复、不指向不存在的页面；
- 所有页面路由都有对应 DOM 节点，且每页都有七个固定信息区或明确的空状态提示。

校验失败必须退出并报错，不能继续生成残缺产物。

## 6. 视觉原则

延续现有单文件实现：浅色画布、固定侧栏、状态色、实体卡片和可点击 SVG。说明页强化“结论卡 + 分区卡”的层次，降低字段堆叠感；移动和打印布局保持可读。大图不放依赖、资金和判断等细节。

## 7. 验收标准

- `node tools/build-docs.mjs` 成功生成单文件 HTML；
- 生成器输出节点数与说明页数量一致；
- `pendingBlocks` 不再产生“待补”导航；
- 全景图每个可点击框都能打开说明页；
- 导航无重复项、无悬空链接；
- 优惠券、退税、行程规划、AI / GEO 等已知口径与事实基座一致；
- VIP 不出现在当前业务全景节点中；
- 产物可在本地浏览器独立打开。
