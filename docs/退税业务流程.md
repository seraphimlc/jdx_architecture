# 退税业务流程

> 2026-10-01 用户确认的业务流程。退税仍在开发阶段，国税厅接入状态待确认，转账网关尚待完成对接；流程已确认不代表接口已接通。

## 已确认的业务规则

- 退税是独立业务；交易退款属于原交易取消或售后的逆向环节。
- 游客先支付含税购物款。示例：含税价 11,000，其中税额 1,000。
- 店员填报资料，平台建立退税业务单；游客确认信息、服务费与收款账户后，平台上报国税厅。
- 平台取得海关确认可退税的结果后，通知商户财务付款。商户将退税全额汇入我方公司指定收款账户，平台核对实际到账。
- 退税额 1,000 对应商户付款 1,000；平台保留 150 服务费，将 850 划入转账网关出款账户并发送指令，由网关转给游客。
- 游客收款账户目标为支付宝、微信或银行卡。报送受理、海关确认、商户到账和游客到账分别记录，不能互相代替。

## 操作流程

| 步骤 | 角色与动作 | 业务结果及资金关系 |
|---|---|---|
| 1. 含税购物 | 游客在商户购物并支付含税款 | 示例：游客支付 11,000，其中税额 1,000；购物款先进入商户账户 |
| 2. 店员登记 | 店员核验游客购买资格，登记身份、商品、消费凭据及税额 | 将本次消费与游客身份关联 |
| 3. 建立退税单 | 平台根据店员提交的信息建立独立退税业务单 | 记录退税额 1,000、服务费 150、预计实收 850 |
| 4. 游客确认 | 游客确认退税资料、服务费及指定收款账户 | 明确应收金额和收款对象 |
| 5. 上报国税厅 | 平台校验并报送购买记录，保存受理结果 | 报送成功后等待海关确认；受理成功不代表可出款 |
| 6. 海关确认 | 游客携带商品，在购买日起 90 日内出境时办理海关确认 | 海关确认对应购买记录能否免税 |
| 7. 平台取得结果 | 平台通过国税厅系统查询、保存海关确认结果，并更新退税单 | 已确认可退税的业务单进入付款流程；无结果继续等待；不可退税的不进入付款流程 |
| 8. 通知商户财务 | 平台按已确认可退税的业务单生成付款清单，通知商户财务付款 | 列明退税单、退税全额及我方公司指定收款账户 |
| 9. 商户全额付款 | 商户财务按约定时限，将退税全额汇入我方公司指定收款账户，并提供打款记录 | 示例：商户汇入 1,000，不预先扣除 150 服务费；付款记录关联对应退税单或付款清单 |
| 10. 核对实际到账 | 平台核对付款记录、商户、退税单和金额，确认款项实际到账 | 付款记录用于匹配，实际到账是后续出款的资金条件 |
| 11. 划款并发出指令 | 平台保留 150 服务费，将游客应收的 850 划入转账网关出款账户，并发送游客收款信息及出款指令 | 商户汇入我方公司账户与平台划入网关账户是两笔不同的资金动作 |
| 12. 游客收款与对账 | 网关执行转账并反馈结果；平台更新退税单、通知游客及商户，核对全部收支 | 记录游客实收 850、服务费 150 及网关结果；游客到账后完成该笔退税与对账 |

## 异常分支

- 报送失败：修正后重新报送，不能仅凭本地退税单进入后续付款流程。
- 无海关确认结果：继续等待，不能视为已确认或不可退税。
- 海关确认不可退税：不列入商户付款清单。
- 商户未打款、少打款、记录无法匹配或尚未到账：保持待处理，核对处理后再出款。
- 网关处理中：查询原笔结果，不能重复创建出款。
- 转账失败：核对失败原因，必要时补正收款信息；确认原笔未成功后再处理重试。

## 尚待落实

- 国税厅与转账网关的具体接口及接入方式。
- 商户打款记录的获取方式。
- 向商户发出付款通知后的约定付款时限，不预设每日、每周或 T+N 周期。

## 官方制度依据

本流程针对 2026 年 11 月 1 日起的日本购物免税新制。

- 游客先按含税价格购物；商户在取得海关确认信息后，返还相应消费税。
- 游客在购买日起 90 日内的出境时办理海关确认，按要求出示护照及商品。
- 购买记录报送成功只是资料被受理，并不代表商品已通过海关确认。
- 海关确认结果通过国税厅的免税销售管理系统查询取得，采用 PULL 方式。提供的结果包括“税関確認済”和“免税不可”；无结果不能直接当作失败。
- 国税厅未在消费税法令中统一规定具体返款方式；商户可以自行办理，也可以委托办理。本项目的收款账户和资金划转方案来自用户确认的业务安排。
